# NexaPress Access Guard

> 最新バージョン: 1.1.1（2026-10-31）。ローカルの未公開変更を反映し、ソースと配布物を揃えた同期リリースです。

NexaPressのログインページと管理画面へのアクセスを保護する、軽量なセキュリティ拡張機能です。

NexaPressへの基本同梱を想定していますが、拡張機能単体でもインストールできます。

## バージョン

```text
1.1.1
```

### 1.1.0の追加機能

- ユーザーごとの二要素認証（認証アプリのTOTP・1回限りの復旧コード）
- ログイン・アクセス拒否・保護設定変更の監査ログと、異常時のメール通知
- 信頼するIP・CIDRを明示するリバースプロキシ対応
- サーバー上でアクセス制限・ログインロック・二要素認証を復旧するCLI

既存の設定は引き継ぎます。二要素認証は本人が登録するまで未登録、プロキシ対応とメール通知は初期状態では無効です。監査ログは初期状態から記録します。

### 1.0.3のセキュリティ改修

- 設定JSONの破損・型不正・読み込み不能時に保護を無効化せず、503で停止します。
- 設定とログインロックの保存を、排他ロック・原子的なファイル置換・バックアップ付きに変更しました。
- 設定画面と全設定保存URLで、本体の`extensions.manage`権限を確認します。
- IPとアカウントの両方でログイン失敗を累積し、連続失敗に待機時間を設けます。
- IPv6の省略形・大文字小文字・IPv4射影表記を正規化し、IP制限と自己締め出し防止へ適用します。

## 対応環境

- NexaPress 2.1.0以上
- PHP 8.0以上
- Apache
- PHP ZipArchive
- PHP OpenSSL（二要素認証を使用する場合）

## 主な機能

### ログインページアクセス制限

許可IPに登録されたIPアドレスだけが、ログインページへアクセスできるようにします。

- 有効・無効の切り替え
- 許可IP以外からのアクセスを拒否
- 現在のIPが未登録の場合は有効化を防止

### 管理ページアクセス制限

許可IPに登録されたIPアドレスだけが、`/admin`以下の管理ページへアクセスできるようにします。

- 有効・無効の切り替え
- 許可IP以外からのアクセスを拒否
- 現在のIPが未登録の場合は有効化を防止

### ログインページ変更

標準のログインURLを任意のURLへ変更します。

標準URL：

```text
/admin/login
```

変更例：

```text
/secure-login
```

機能を有効にすると、元の`/admin/login`は404になります。

### ログインロック

同じIPアドレス、または同じアカウントへのログイン失敗が指定回数に達した場合、一時的にログインをロックします。IPを変更してもアカウントの制限は引き継がれます。

選択できる失敗回数：

- 3回
- 5回
- 10回

選択できるロック期間：

- 5分
- 15分
- 30分
- 1時間
- 6時間
- 24時間

失敗履歴の観測期間は15分です。連続する2回目の失敗から、1秒・2秒・4秒…最大30秒の待機時間を設けます。

ログイン成功時は、そのアカウントの失敗回数をリセットします。正しい認証情報を使った制限回避を防ぐため、IP全体の失敗履歴は観測期間中維持します。

### フェールワンス

許可IPに登録されていないIPアドレスから正しいログイン情報が送信された場合でも、指定回数だけ意図的にログインを失敗させます。

選択できる回数：

- 1回
- 2回
- 3回

許可IPからのログインでは発動しません。

### 許可IP

信頼するIPアドレスを登録します。

許可IPは次の機能で使用されます。

- ログインページアクセス制限
- 管理ページアクセス制限
- フェールワンスの対象外

現在接続しているIPアドレスは、設定画面上部に表示されます。

### 拒否IP

登録されたIPアドレスから、ログインページと管理ページへのアクセスを拒否します。

現在接続しているIPアドレスは、誤操作防止のため拒否IPへ登録できません。

### 二要素認証

アクセスガード設定画面の「自分の二要素認証を設定」から登録します。他の権限のユーザーも`/admin/access-guard/two-factor`で自分のアカウントを設定できます。他人の設定は変更できません。

1. 現在のパスワードを入力して登録を開始します。
2. 表示されたセットアップキーを認証アプリへ登録します。アプリへのリンクも利用できます。キーを外部のQRコード生成サービスへ送信しません。
3. アプリの6桁のコードを入力すると有効になります。
4. 10件の復旧コードが一度だけ表示されます。安全な場所へ保管してください。

パスワード確認後、追加の確認コードが通るまでログインを完了しません。認証手順の有効期限は5分で、コードを5回間違えるとアカウント単位で5分間制限します。TOTPは30秒ごとに更新し、前後1区間の時刻ずれを許容します。一度使った時刻区間のコード・復旧コードは再利用できません。登録時に使用したコードがログインに使えない場合は、次のコードへ切り替わるまで待ってください。

秘密鍵はAES-256-GCMで暗号化し、復旧コードはハッシュだけを保存します。有効化前のセッションや復旧コード再発行前の他のセッションには再ログインを要求します。解除・復旧コード再発行には現在のパスワードと有効な確認コードまたは復旧コードが必要です。本番環境ではHTTPSで利用してください。

### 監査ログ・異常通知

監査ログにはログイン成功・失敗、アクセス拒否、二要素認証の変更、復旧コードの利用、設定変更、CLI復旧を記録します。パスワード・確認コード・秘密鍵・復旧コードの値は記録しません。管理画面では最新100件をUTCで表示します。

保持期間は7・30・90日から選択でき、最大2,000件です。保持期間を過ぎたログは次回記録時に削除します。ログ保存に失敗した場合はPHPエラーログへ記録し、ログ障害だけを理由に認証を停止しません。

通知先メールアドレスを設定して有効にすると、5分以内に指定回数（5・10・20・50回）の認証失敗があった場合、保護設定の無効化、二要素認証の解除、復旧コード利用、CLI復旧を通知します。同じ種類の通知は5分間に1回までです。通知を無効にする操作自体は、変更前の通知先へ通知します。

通知にはサーバーのPHP `mail()`を使用します。サーバー側のメール送信設定が必要です。NexaPress Mail拡張の送信アカウントとは独立しています。送信失敗は監査ログとPHPエラーログに記録します。

### 信頼済みプロキシ

設定画面で管理するプロキシのIPまたはCIDRを1行1件で登録し、`X-Forwarded-For`・`X-Real-IP`・`CF-Connecting-IP`から使用するヘッダーを選びます。直近の接続元が信頼リストと一致したときだけヘッダーを使用します。`X-Forwarded-For`は右側からたどり、最初の信頼されていないIPを利用者IPとして採用します。

プロキシ側で外部から渡された転送情報を適切に上書き・追記してください。すべての接続元を信頼する`/0`は登録できません。信頼するプロキシ経由でヘッダーが欠落・不正な場合、管理関連ページは403になります。

IP制限が有効な場合は、変更後に判定される利用者IPも先に許可IPへ追加してください。設定保存時に自分がアクセス不能になる変更を防止します。

### サーバーからの復旧CLI

Webアクセスを使わず、サーバー上でPHP CLIを実行します。`--base-path`にはNexaPress本体の`app`と`storage`がある絶対パスを指定します。以下の`/var/www/nexapress`は実際の設置先へ置き換えてください。

```sh
php bin/access-guard.php status --base-path=/var/www/nexapress
php bin/access-guard.php restore --base-path=/var/www/nexapress --file=settings
php bin/access-guard.php disable-access --base-path=/var/www/nexapress
php bin/access-guard.php allow-ip --base-path=/var/www/nexapress --ip=192.0.2.10
php bin/access-guard.php unlock --base-path=/var/www/nexapress --ip=192.0.2.10 --username=admin
php bin/access-guard.php disable-two-factor --base-path=/var/www/nexapress --user-id=1
```

`restore`の対象は`settings`・`login-locks`・`two-factor`に限定します。`disable-access`はログイン・管理IP制限、変更したログインURL、プロキシ判定を無効にします。拒否IPは保持するため、必要なら`allow-ip`で対象IPを許可してください。二要素認証の解除は対象ユーザーIDだけに適用します。変更操作は監査ログへ記録します。復旧後は必要な保護を再設定してください。

## 設定画面

全体設定は、1つの管理画面に表示されます。本人の二要素認証は専用画面で設定します。

設定画面の閲覧と設定変更には、本体の「拡張機能管理」権限（`extensions.manage`）が必要です。標準の権限構成では管理者のみが操作できます。

各機能は個別のフォームになっているため、保存もそれぞれ独立しています。

```text
ログインページアクセス制限
├─ 有効・無効
└─ この設定を保存

管理ページアクセス制限
├─ 有効・無効
└─ この設定を保存

ログインページ変更
├─ 有効・無効
├─ 変更後URL
└─ この設定を保存

ログインロック
├─ 有効・無効
├─ 失敗回数
├─ ロック期間
└─ この設定を保存

フェールワンス
├─ 有効・無効
├─ 失敗させる回数
└─ この設定を保存

許可IP
├─ IP追加
└─ 登録済みIPの削除

拒否IP
├─ IP追加
└─ 登録済みIPの削除
```

## インストール方法

1. 配布用ZIPを用意します。
2. NexaPressの管理画面へログインします。
3. 「拡張機能」を開きます。
4. ZIPファイルをアップロードします。
5. 「NexaPress Access Guard」を有効化します。
6. 拡張機能メニューから「アクセスガード」を開きます。

## 安全な初期設定手順

管理画面へアクセスできなくなる事故を防ぐため、次の順番で設定してください。

1. NexaPress Access Guardを有効化する
2. 設定画面を開く
3. 画面上部に表示された現在のIPを確認する
4. 現在のIPを「許可IP」へ追加する
5. ログインロックを設定する
6. フェールワンスを設定する
7. ログインページ変更を設定する
8. ログインページアクセス制限を有効にする
9. 管理ページアクセス制限を最後に有効にする

ログインページを変更した場合は、変更後のURLを必ず控えてください。

## 設定データの保存場所

設定やログインロック情報は、拡張機能フォルダ外へ保存されます。

```text
storage/
└─ extensions/
   └─ access-guard/
      ├─ settings.json
      ├─ settings.json.bak
      ├─ settings.json.lock
      ├─ login-locks.json
      ├─ login-locks.json.bak
      ├─ login-locks.json.lock
      ├─ two-factor.json
      ├─ two-factor.json.bak
      ├─ two-factor.json.lock
      ├─ two-factor.key
      ├─ two-factor.key.lock
      ├─ audit.json
      ├─ audit.json.lock
      ├─ notifications.json
      ├─ notifications.json.lock
      └─ fail-once.json
```

そのため、拡張機能本体を更新しても設定データは維持されます。

二要素認証を含めて移行・バックアップする場合は、`two-factor.json`と`two-factor.key`を必ずセットで安全に保管してください。暗号鍵が失われたときは別の鍵を自動生成しません。鍵を復元できない場合は、CLIで対象ユーザーの二要素認証を解除して再登録してください。

### 保護データの破損時の復旧

初回起動で保存データがまだない場合は初期設定を使用します。既存の設定JSONが破損・型不正・読み込み不能の場合、またはバックアップがあるのに元ファイルが消失した場合は、保護を解除せず503で停止します。設定を読み込めない場合は公開ページを含むサイト全体、ログインロック情報を読み込めない場合はログイン処理が停止します。

サーバー上で破損ファイルを退避し、内容を確認した`settings.json.bak`を`settings.json`へ、または`login-locks.json.bak`を`login-locks.json`へコピーして復旧してください。バックアップは自動で適用しません。保存処理が途中で失敗した場合、バックアップには保存を試みた設定が含まれることがあるため、適用前に確認してください。

ファイルと保存フォルダはPHPから読み書きできる権限にしてください。`.lock`ファイルは稼働中に削除しないでください。

## 配布用ZIPの作成

プロジェクトフォルダへ移動します。

```bat
cd /d D:\github作業フォルダ\nexapress-access-guard
```

PHPファイルを一括で構文チェックします。

```bat
for /R %f in (*.php) do @php -l "%f"
```

すべてのPHPファイルで次のように表示されることを確認します。

```text
No syntax errors detected
```

その後、配布用ZIPを作成します。

```bat
php build.php
```

正常に完了すると、次のZIPが作成されます。

```text
dist\nexapress-access-guard-1.1.1.zip
```

作成されたZIPを確認します。

```bat
dir dist
```

## 拡張機能の更新について

`manifest.json`には、将来の拡張機能更新機能で使用する更新元情報を含めています。

```json
"update": {
  "provider": "github",
  "repository": "aki-sho/nexapress-access-guard",
  "asset": "nexapress-access-guard-{version}.zip"
}
```

現在のNexaPress本体には、拡張機能を個別に自動更新する処理はまだありません。

今後、本体側へ拡張機能更新機能を追加した際に、GitHub Releasesから更新情報と配布用ZIPを取得できる構成にしています。

## 注意事項

### IPアドレスについて

初期状態では、接続元IPとしてPHPの`REMOTE_ADDR`を使用します。

リバースプロキシ、CDN、ロードバランサー環境では「信頼済みプロキシ」を設定してください。未設定の場合はプロキシ側のIPが表示される場合があります。

### 動的IPについて

インターネット接続環境によっては、IPアドレスが定期的に変更されます。

IPアドレスが変わる環境で管理ページアクセス制限を有効にすると、管理画面へ入れなくなる可能性があります。

### ログインURLについて

ログインページ変更を有効にした場合、標準の`/admin/login`は使用できません。

変更したURLを忘れないように保管してください。

### テストについて

PHP CLIで回帰テストを実行できます。HTTPテストにはPHP cURL拡張が必要です。

```text
php tests/run.php
php tests/security.php
php tests/features.php
```

設定破損時の503、全設定保存URLの権限とCSRF、分散したログイン失敗、IPv6の別表記、並行保存時のデータ維持に加え、RFC 6238のTOTPテストベクトル、二段階ログイン、コード再利用防止、通知制限、プロキシ偽装、CLI復旧を確認します。テストのメール送信は捕捉し、外部へ送信しません。

本番環境で有効にする前に、ローカル環境または検証環境で動作を確認してください。

特に次の機能は、必ず個別に確認してください。

- ログインページ変更
- ログインページアクセス制限
- 管理ページアクセス制限
- ログインロック
- フェールワンス
- 許可IP
- 拒否IP

管理ページアクセス制限は、必ず最後に確認してください。
